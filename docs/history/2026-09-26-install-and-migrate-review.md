# Block 5 adversarial review (2026-09-26)

Scope: `install --write` merge (hooks `setup.ts`/`cli.ts`), `migrate` to a key reference (`core/src/migrate.ts`, `cli/src/commands.ts`), the deterministic stale-lock test. Read-only on `/home/claude/irontrellis-next`; all experiments ran in `/tmp/review-b5/tree` (and a mutant copy `/tmp/review-b5/treeM`). PoC scripts: `/tmp/review-b5/poc/install-poc.mjs`, `/tmp/review-b5/tree/packages/core/test/zz-poc-migrate.test.mjs`, `/tmp/review-b5/poc/m1cli/`, `/tmp/review-b5/{tree,treeM}/packages/core/test/zz-store-retry.test.mjs` + `zz-lock-race-worker-retry.mjs`.

## High

### H1. `install --write` "repairs" a planted narrow-matcher copy by deleting the real catch-all guard (and accepts a guard scoped away)
`planSettings` keeps the *first* handler `isOurs` finds and removes later ones as "duplicates", and on update keeps the handler's matcher group. It never looks at the group's `matcher`. Our entries are written with no matcher (all tools).

PoC (`node /tmp/review-b5/poc/install-poc.mjs`, cases A1/A2), Claude Code `.claude/settings.json`:
```
PreToolUse: [ {matcher:"NoSuchTool", hooks:[<ours exactly>]}, {hooks:[<ours exactly>]} ]
-> changes: removed hooks.PreToolUse (duplicate), unchanged hooks.PreToolUse
-> after:   [ {matcher:"NoSuchTool", hooks:[<ours>]} ]          # the working guard is gone
PreToolUse: [ {matcher:"Read", hooks:[<ours>]} ]
-> "= hooks.PreToolUse ... unchanged"; with --write: "is up to date; nothing written"
```
An agent that can write `.claude/settings.json` (or `.codex/hooks.json`) prepends one group, and the operator's re-install - the obvious repair step - deletes the real guard and reports success. Bash/Write/Edit then never reach IronTrellis.

Fix: treat a handler as correctly installed only when its group matcher is absent, `""` or `"*"`. Prefer keeping the copy in a catch-all group; a copy under any other matcher is either removed-and-re-added in a catch-all group (report it as `~ moved out of matcher "X"`) or, given the "refuse, don't guess" policy, makes install exit 1 naming the matcher. Add both cases to `hook.test.mjs`.

## Medium

### M1. `migrate` with a key reference + `--reuse-existing-key` adopts an on-disk PRIVATE key, and the CLI says "reference (no secret)"
The reuse check only compares `signer.scheme`/`credential` against `reference.publicKey`; it does not require the existing file to be a reference (`custody.holder === "reference"`). The CLI then derives "holder" from the flags, not from the file.

PoC (`/tmp/review-b5/poc/m1cli/`): an ordinary owner key file (with `privateKey`) at `t.jsonl.owner-key.json`, then
`irontrellis migrate legacy.jsonl t.jsonl --reuse-existing-key --signer ssh-agent --agent-socket <nonexistent.sock> --public-key <that key>` succeeds and prints
`owner key owner:1 held by key file .../t.jsonl.owner-key.json · .../t.jsonl.owner-key.json is a reference (no secret; mode 0600)`; `grep -c privateKey` on the file = 1. JSON output says `ownerKeyHolder: "reference"`. Core PoC: `zz-poc-migrate.test.mjs` "PoC M1" (holder `file`, privateKey true).

The operator asked for agent custody and is told there is no secret on disk; the target is actually signed by (and remains controlled by) a plaintext key on disk, and the named agent was never used.

Fix: in reference mode, with `reuseExistingKey`, require `loadOwnerKeyFile(keyPath).custody.holder === "reference"` and the same signer description (kind + socket/command/vault key), else `KEY_EXISTS`. In the CLI take `ownerKeyHolder` from `loadOwnerKeyFile(keyFile).custody.holder`, never from the flags.

### M2. `migrate` writes the target and the reference before any successful signature when the source has no control events after genesis
The reference file is written before signing; for a genesis-only source no `signControlEvent` runs during the dry run, so the first signature attempt is the pin attestation in `target.flush()`, *after* the target is written. The cleanup does not run on that path.

PoC (`zz-poc-migrate.test.mjs` "PoC M2"; agent lacks the key): `KEY_UNAVAILABLE the target history was written, but its pinned head could not be attested ...`; target exists: true, reference exists: true, and `verifyHistory(target)` reports ok with pin `MATCHES`. The genesis now commits to a public key nobody proved possession of (a typo, or someone else's key), and the notes' claim "a signer that cannot sign fails before any target byte is written" is false for this input.

Fix: prove possession before writing anything: after building the signer (reference or otherwise), sign a fixed challenge (or the migrated genesis/pin statement) and verify it against `reference.publicKey`; on failure unlink the created reference. Also wrap the whole post-creation section in one `try/finally` that removes `createdKeyFile` when the target was not created (today an exception from `migratedGenesis`/`reRecorded` also leaks it).

### M3. The deterministic lock test no longer detects a reclaimer that deletes the holder's live lock
With the barrier design and `lockTimeoutMs` 0 the loser makes exactly one attempt, and nobody attempts again while the winner is inside. So a store that renames a live lock aside and never links it back (lock path empty while the winner holds) passes.

PoC: in `/tmp/review-b5/treeM` `#reclaimLock`'s link-back block is deleted. The unmodified block-5 test **passes** on the mutant ("wins 54/66, live locks displaced and relinked 98": the diagnostic label is also wrong there, since nothing was relinked). Adding one retry by the loser after its `STORE_BUSY`, while the winner is still inside (`zz-lock-race-worker-retry.mjs`): original tree passes (0 violations, 94 displacements), mutant **fails with 94 violations**.

Fix: add the loser's in-round retry (as in the PoC), and/or have the winner assert, before leaving its critical section, that the lock path is still its own file (same inode as the lock it created, pid = its own). Count "relinked" from the `linkSync` wrapper rather than inferring it from displacements.

### M4. `install --write` is not atomic
`writeFileSync(file, after)` opens the existing settings with `O_WRONLY|O_CREAT|O_TRUNC` (strace: `openat(".../.claude/settings.json", O_WRONLY|O_CREAT|O_TRUNC)`) and writes in place. A crash/ENOSPC/kill leaves an empty or truncated settings file; a host reading it concurrently can see an empty file. For Claude Code an unparsable settings file means no hooks, i.e. no guard. There is also no re-check between read and write (a concurrent edit by the user or host is lost).

Fix: write `<file>.tmp-<pid>` (same dir, mode of the original), fsync, `rename` over `realpathSync(file)` so a symlinked settings file stays a symlink (the current code follows symlinks, which is the right behaviour to keep), fsync the dir; before renaming, re-read the file and abort if its bytes differ from `text`.

## Low

- **L1. A user's wrapper around the hook is silently replaced.** Any token whose basename is `irontrellis-hook` makes the entry "ours". PoC A4: `env IRONTRELLIS_HOME=/srv/it /usr/local/bin/audit-log irontrellis-hook claude-code PreToolUse` is `~ updated` to bare `irontrellis-hook claude-code PreToolUse`, dropping the env and audit wrapper (the hook then reads the wrong state home). Fix: recognise only programs whose *first* token (after `npx [flags] [-p pkg]`) is the hook, or that equal `--command`; everything else that mentions the hook is ambiguous, so refuse it.
- **L2. The ambiguity net is case-sensitive and substring-based, so look-alikes stay.** PoC A6: `IronTrellis-Hook claude-code PreToolUse --bypass` is neither ours nor ambiguous (the substring check is case-sensitive, `isHookProgram` is not), so it is kept next to ours. A7: `IRONTRELLIS_FAIL_OPEN=1 irontrellis-hoo''k claude-code PreToolUse` (runs the hook under the shell) is kept. Ours still runs, and for Claude Code a deny wins, so impact is low. But install cannot be relied on to flush planted look-alikes. Fix: match case-insensitively, and report (at least warn about) any other handler in an installed event whose command ends in ` <agent> <Event>`.
- **L3. `disableAllHooks` (Claude Code) is kept and not reported.** PoC A3: `{"disableAllHooks": true, hooks:{PreToolUse:[ours]}}` gives "up to date". A planted top-level switch neutralises every hook, and the operator's install prints success. Fix: warn loudly (or refuse without `--force`) when `disableAllHooks` is true; mention `.claude/settings.local.json` in the output since it overrides the file install writes.
- **L4. Switching away from a custom `--command` leaves two guards.** PoC A11: install with `--command /opt/wrap/guard`, then plain install gives both `/opt/wrap/guard claude-code PreToolUse` and `irontrellis-hook claude-code PreToolUse`: every call is evaluated twice (double session admission, double records). Fix: allow `--replace-command <old>`, or print a hint when a handler in the event ends in the exact ` <agent> <Event>` tail but is not recognised.
- **L5. Unrelated values can change silently.** The JSON round trip turns `12345678901234567890` into `12345678901234567000` and `1.0` into `1` (PoC: `/tmp/review-b5/poc/real/settings.json`). The `--write` summary lists only hook changes, and only `--dry-run` shows the diff. Fix: if re-serialising the *original* document does not reproduce the original values (e.g. `JSON.parse(JSON.stringify(x))` compare plus a lossless-number check), refuse or print the diff with `--write` too.

## Verified OK
- `--dry-run` never writes: inode, mode and mtime unchanged (also when `--write` is given together with it; `cli.ts` passes `write && !dryRun`).
- Symlinked settings: written through the link, the link is kept, and mode 0600 is preserved (not atomic, see M4).
- Idempotent: a second `--write` prints "up to date; nothing written", and the bytes are identical (`cmp`).
- Unrelated top-level keys, key order, event order, other events and user handlers are kept; group-level extra keys are kept (A8).
- Malicious look-alikes that `isOurs` matches are replaced, not kept: `curl …|sh; irontrellis-hook claude-code PreToolUse` (A10), Cursor handler with `matcher: "NoSuchTool"` (A9, `failClosed` restored).
- Commands that mention `irontrellis-hook` without the exact tail (e.g. `/opt/irontrellis-hook/../lint.sh …`) are refused, not deleted (A5). Malformed JSON and an empty file are refused.
- Migrate key reference: written by `writeKeyText` (tmp `wx` 0600 + `link`, no clobber, no secret); no key material is generated in reference mode; `signer`+reference gives `INVALID_INPUT`; a mismatched reused key gives `KEY_EXISTS`; for sources with control events, a missing agent key fails before the target is written and the reference is removed (block-5 test, re-read).
- Lock test: no vacuous assertions (reclaim count 0 or 2 would fail; violations are detected via the `wx` marker; outcome length and per-round W/B checked); passes on the original tree; the retry-augmented variant also passes on the original tree (no false positive). Only gap: M3.

Processes: the lock test runs and the per-test ssh-agents exited (the only `ssh-agent` left, `/tmp/claude-0/sshproto/a.sock`, predates this review and was not touched).
