`observeHistory(events, { at?, expectHead? })` captures and replays a caller-supplied history (an `exportHistory()` array, a parsed `irontrellis export`, a `store.readAll()`); `observeState(state, options, defaultAt?)` wraps an already replayed state. Default `at` is the head time for `observeHistory` and the host clock for an owner handle. An `Observation` is frozen: `{ head, evaluationTime, scope: "CAPTURED_HISTORY_ONLY", eventCount, authorize(action), why(action), responsible(action), survives(agent) }`.

`Decision` = `{ scope: "CAPTURED_HISTORY_ONLY", executionCapability: false, head, evaluationTime, decision: "ALLOW" | "DENY" | "INDETERMINATE", evidence: AuthorizationResult }`. `AuthorizationResult` is `{ operationVersion: "continuity-authorization/0.2", decision: "ALLOW", scopeAssurance: "REPLAY_VERIFIED", consequential, proof }` or `{ …, decision: "DENY" | "INDETERMINATE", consequential: false, code, failures: [{ code, subjectId?, rootAuthorityId?, terminalAuthorityId?, failingAuthorityId?, authorityPathIds, evidence: [EVENT references] }] }`. Denial codes: `DOMAIN_MISMATCH POLICY_MISMATCH INVALID_REQUEST INVALID_AMOUNT INVALID_DELEGATION AGENT_INACTIVE SESSION_NOT_FOUND SESSION_EXPIRED SESSION_CREDENTIAL_REQUIRED SESSION_CREDENTIAL_INVALID SESSION_FENCED STALE_EPOCH ROLE_TENURE_NOT_CURRENT INTENT_REQUIRED INTENT_NOT_DECLARED INTENT_MISMATCH INTENT_REPLAY NONCE_ALREADY_ADMITTED PROHIBITED REVOKED NOT_YET_VALID EXPIRED MISSING_INTERSECTION ACTION_NOT_ALLOWED RESOURCE_NOT_ALLOWED AMOUNT_REQUIRED AMOUNT_EXCEEDED CUMULATIVE_AMOUNT_EXCEEDED TRANSACTION_COUNT_EXCEEDED NO_AUTHORITY`. Indeterminate codes: `INVALID_INPUT UNSUPPORTED_VERSION STATE_NOT_AUTHORITATIVE HISTORY_RELATION_UNVERIFIED CAUSAL_TIME_INVALID OUTPUT_LIMIT_EXCEEDED EVIDENCE_UNAVAILABLE EVIDENCE_DISPUTED`. The proof shape is `docs/HISTORY-FORMAT.md` §8.3.

What a DENY or INDETERMINATE cites depends on the format. The output budget is 4,096 evidence references in both.

* **Format 1** cites only the events relevant to the request: the genesis, the head, the actor's lifecycle (`AGENT_CREATED`, `AGENT_TERMINATED`, `CONTROL_EPOCH_ADVANCED`), the grant and revocation events of every authority on the actor's candidate paths and of their intersection partners, and every prohibition considered (relevant GLOBAL ones, the candidates' ROOT ones); for a consequential request with a binding, also the session, role-tenure and intent events the binding names. `INTENT_REQUIRED` denials are narrowed the same way.
* **Legacy** histories keep the reference's evidence byte for byte (spec 02 §6.2, [docs/legacy-semantics/02-authorization.md](../legacy-semantics/02-authorization.md)): a candidate-path, `NO_AUTHORITY` or global `PROHIBITED` denial cites every authority event in the history, and `INTENT_REQUIRED` every intent of the actor, so on a legacy history with many grants a DENY can come back as `INDETERMINATE / OUTPUT_LIMIT_EXCEEDED`.

## 6. Query envelopes

`why`, `responsible` and `survives` return envelopes with `version: "continuity-query-envelope/0.2"`, `kind`, and either `epistemicStatus: "ESTABLISHED"` with `scope` and `answer`, or `epistemicStatus: "INDETERMINATE" | "UNAVAILABLE" | "DISPUTED"` with `code` and `evidence`. `scope` names the domain, versions, policy, recognized roots, lineage, the evaluation and observed heads, `headRelationship` (`SAME_HEAD` | `STRICT_EXTENSION` | `UNVERIFIED`), `freshness`, `finality: "LOCAL_ONLY"`, the `disclosure` (`PUBLIC_MINIMAL` with the included and withheld fields), unavailable and withheld evidence, and the external assumptions.

Answers: WHY `{ authorization, presentConsequentialUse }`; RESPONSIBLE `{ authorizationDecision, attributions: [{ kind, subjectId, temporalBasis: "ACTION_PREFIX" | "LATER_CAUSAL_STATE", evidence }] }` with kinds `ACTOR RUNTIME_SESSION ROLE DECLARED_PRINCIPAL MANDATOR AUTHORITY_SOURCE CONTROLLER DURABLE_OBLIGOR PERFORMANCE_ASSIGNEE BENEFICIARY COUNTERPARTY`; SURVIVES `{ targetAgentId, exists, lifecycleStatus: "ABSENT" | "ACTIVE" | "TERMINATED", historicalIdentity, currentRoleTenures, transferredRoleTenures, unresolvedIntents, adapterOutcomes, outcomeObservations?, attemptDuties?, receiptCommitments, obligations, currentPerformanceAssignments, invalidatedAuthorityDependencies }`, every row carrying its evidence references. Evidence reference shapes are `docs/HISTORY-FORMAT.md` §6.3. The full type definitions are exported (`WhyQueryResult`, `ResponsibleQueryResult`, `SurvivesQueryResult`, `SurvivesAnswer`, …).

```js
import { openHistoryStore, loadOwnerKeyFile, ownerKeyPathFor, anchorsPathFor, localAnchorLog, anchorHead } from "@ramex-labs/irontrellis";
const store = openHistoryStore("./history.jsonl");
const signer = loadOwnerKeyFile(ownerKeyPathFor("./history.jsonl"));   // refuses a key file group or others can read
const anchored = await anchorHead(store, signer, localAnchorLog(anchorsPathFor("./history.jsonl")), { id: "anchor:1", anchoredAt: Date.now() });
anchored.event.type;                 // ANCHOR_RECORDED
const report = owner.verify();
report.anchors;                      // [{ head, anchor: 'local-head-file', eventId: 'anchor:1', status: 'PREFIX_OK' }]
report.anchorLogStatus;              // OK (every head in history.jsonl.anchors is a prefix of the file)
```

* `Signer` = `{ keyId, scheme, credential, signHash: (hash) => Promise<HexSignature>, signHashSync?: (hash) => HexSignature }`. `credential` is the `0x` + 64 hex raw Ed25519 public key or an address. Provide your own to keep the key in a KMS or HSM (`docs/SECURITY.md` §3 has a complete example); local keys also expose `signHashSync`, which lets the store attest a pin in the same synchronous turn as the append.
* `createOwnerKeyFile(path, keyId = "owner:1")` → `Signer` (Ed25519, `O_EXCL`, 0600; `KEY_EXISTS` if present). `loadOwnerKeyFile(path)` → `Signer` (`KEY_UNAVAILABLE` on any defect, a next-key file included; on POSIX systems also for a file with any group or other permission bit set, with `detail` `{ path, mode, requiredMode: 0o600 }`). `ownerKeyPathFor(historyFile)` = `<historyFile>.owner-key.json`.
* Next-key files (pre-rotation): `createNextOwnerKeyFile(path, keyId = "owner:next")` → `Signer` (Ed25519, version `OWNER_NEXT_KEY_VERSION` = `irontrellis-owner-next-key/1`, 0600, written through a temporary file linked into place; `KEY_EXISTS` if present); `loadNextOwnerKeyFile(path)` → `Signer` (same checks; an owner key file is refused); `promoteNextOwnerKeyFile(from, to, keyId)` → `Signer` (writes the next key as an owner key file, `OWNER_KEY_VERSION`); `nextOwnerKeyPathFor(historyFile)` = `<historyFile>.owner-next-key.json`, `pendingNextOwnerKeyPathFor(historyFile)` = `<historyFile>.owner-next-key.pending.json`.
* `signControlEvent(signer, event, domain, previousHead, algorithm)` returns the event with `data.controlAuthorization`. `attestHead(signer, domain, head, algorithm)` → `HeadAttestation`; `verifyHeadAttestation(attestation, domain, ownerKeys, algorithm)` → boolean (against exactly the keys given).
* Owner key epochs (`docs/HISTORY-FORMAT.md` §7.1): `state.ownerKeyEpochs` is `[{ fromPosition, keys, nextKeyDigests? }]` (`nextKeyDigests`: the epoch's next-key commitment, fixed by the genesis or the rotation that opens the epoch, §7.2). `ownerKeysAt(stateOrEpochs, position)` → the owner keys in force at `position` (for the control event at that position and for an attestation of the head at that position). `ownerKeyInForce(stateOrEpochs, position, { keyId, scheme, credential })` → boolean. `verifyHeadAttestationAt(attestation, state)` → boolean: signed by a key in force at the attested head's position (the store, the remote witnesses and `verify()` all judge pins, anchor-log entries and witness statements this way; whether the head is a prefix of the file is a separate check). `controlSignatureFailure(event, { domain, previousHead, keys, algorithm })` → the reason a control signature fails, or `undefined`. `ownerKeyRotationFailure(epochs, newKeys)` → the key-set rule a rotation breaks, or `undefined`.
* `verifyRotationEvent(event, { domain, previousHead, epochs, openedAt?, historyId?, algorithm? })` checks an `OWNER_KEYS_ROTATED` event without the history, for a party (a remote witness) that knows the previous head and the prior epochs. In format 2 it also applies the policy each epoch records (`epochs[i].policy`): the quorum and counting, the time rule T2 (with `previousHead.canonicalTime`), and policy validity (`openedAt` gives each epoch's opening time, needed under `ATTESTED`; `historyId` is needed when the rotation sets statements). It does not check the rules that need the full history state, and its result adds `stateChecked: false`, `policyRotation`, `restoration`, `recovery`, `quorum` and `openedAt`. A refusal that T2 would decide without `canonicalTime` carries `notJudged: "T2"`; the export verifier then checks again with `omitT2: true` and notes that T2 was not judged. It checks the schema at `previousHead.position + 1`, the owner signature over the control challenge with that `previousHead` by a key in force there, the key-set rules, and the pre-rotation rules against the commitment the given `epochs` record for the epoch the rotation leaves (`ownerKeyEventTransition`). Returns `KeyEventVerification` = `{ ok: true, event, position, fromPosition, keys, reason?, epochs, preRotated, commitmentOnly, nextKeyDigests? }` (`epochs` extended by the new one, `fromPosition = previousHead.position + 2`; `preRotated`: it satisfied a commitment; `commitmentOnly`: it kept every key and only added a commitment; `nextKeyDigests`: the new epoch's commitment) or `{ ok: false, code, reason }` (`code` a replay code: a schema code, `CONTROL_AUTHORIZATION_INVALID` or `TRANSITION_INVALID`; `INVALID_INPUT` for a missing head, a non-rotation event, a missing or malformed `epochs` list, or a bare `keys` set). `epochs` is required: seed it from the genesis (`{ fromPosition: 0, keys: genesis.ownerKeys, nextKeyDigests: genesis.nextKeyDigests }`) so that epoch 0's commitment is enforced. There is no key-set shortcut, because it would drop the commitment silently; a verifier whose `epochs` still lack a commitment the history made judges the rotation valid but not pre-rotated. The Python verifier's `verify_rotation_event(event, domain, previous_head, epochs)` has the same contract. It does not establish that `previousHead` is really the history's head (the caller's chaining rule does) nor the event-id and time-order checks only a full replay makes.
* `ownerKeyEventTransition(epochs, event, { domain, previousHead, algorithm })` is the rule set replay and `verifyRotationEvent` share (for an event whose schema and owner signature were already checked); `keepsEveryOwnerKey(current, keys)` says whether a rotation is commitment-only. `ownerKeyDigest({ scheme, credential })` → the digest a commitment names (`OWNER_KEY_DIGEST_VERSION` = `irontrellis-owner-key-digest/1`). `signedControlEffect(data)` → the part of `data` the owner signatures cover (without `controlAuthorization` and `nextKeyAuthorizations`); `controlEffectHash` hashes it.
* `AnchorContext` = `{ domain, algorithm, ownerKeys, ownerKeysAt?(position) }`; `anchorContextOf(state)` builds it from a replayed state and `contextKeysAt(context, position)` gives the keys a context accepts at a position (a context without `ownerKeysAt` accepts `ownerKeys` at every position). `store.setSigner(signer)` replaces the signer that attests later pins; a signer whose key is not in force at a head never attests it (the pin carries the last valid attestation, `PIN_ATTESTED_EARLIER`), and `repin()` refuses such a signer with `KEY_UNAVAILABLE`.
* `pendingOwnerKeyPathFor(historyFile)` = `<historyFile>.owner-key.pending.json`; `retiredOwnerKeyPathFor(historyFile, keyId)` = `<historyFile>.owner-key.<keyId, sanitized>.retired.json`.
* Openers read `<path>.anchors` (never a Rekor log): a head it holds that is past the file or off its history is `ROLLBACK_DETECTED` with reason `ANCHOR_LOG_ROLLBACK`, and a log that exists but cannot be read is `ANCHOR_LOG_UNREADABLE` (§11). Entries no owner key signed are left to `verify()`.
* Anchor targets: `localAnchorLog(path)` (refuses an attestation that does not verify with `ANCHOR_LOG_REJECTED`) and `rekorAnchor({ baseUrl?, fetch? })` (experimental: never exercised against a live Rekor log; a non-2xx answer is `ANCHOR_LOG_REJECTED`). An `AnchorTarget` is `{ kind, name, submit(attestation, context?), verify?(attestation, receipt, context?), location?, entries?() }` (`kind` is an `AnchorKind`: `local`, `rekor` or `custom`). `entries()` lists every head attestation the target holds, oldest first (`AnchorLogEntry` = `{ attestation, receivedAt? }`), or `undefined` when it holds nothing yet, and throws `ANCHOR_LOG_UNREADABLE` for a log that exists but cannot be read or parsed; `location` is where it keeps them (the local log's absolute path). A target with `entries()` is an anchor log; only the local anchor log implements both, so only it can be consulted by `verify()`. `anchorsPathFor(historyFile)` = `<historyFile>.anchors`, the local log `verify()` always reads. `anchorRecordedEvent(attestation, target, receipt, anchoredAt, id)` builds the unsigned event; `anchorHead(store, signer, target?, { id, anchoredAt })` attests the current head, submits it (to `localAnchorLog(anchorsPathFor(store.path))` when `target` is `undefined`), signs and appends `ANCHOR_RECORDED` under the writer lock, and returns `{ attestation, receipt, event, head }`. Format 1 only (`UNSUPPORTED_VERSION` engine error otherwise). An anchor is evidence about a head: it never binds or unbinds a remote witness (§7a).
* `VerificationReport` (what `store.verify()`, `owner.verify()` and `verifyHistory` return; the owner forms add `rollback: boolean`, true when `pinnedHeadStatus` or `anchorLogStatus` is `ROLLBACK`):

| field | meaning |
|---|---|
| `ok` | `true` exactly when `failures` is empty. Decide on this; the other fields explain it |
| `failures` | each failed check as `"CODE: explanation"`. Codes: `PIN_ROLLBACK`, `PIN_MISSING`, `PIN_MALFORMED`, `PIN_ATTESTATION_MISSING`, `PIN_ATTESTATION_INVALID`, `ANCHOR_MISMATCH`, `ANCHOR_LOG_ROLLBACK`, `ANCHOR_LOG_INVALID`, `ANCHOR_LOG_UNREADABLE`, `ANCHOR_LOG_MISSING` (`docs/OPERATOR.md` §6 says what each means; remote-witness codes below) |
| `notes` | informational findings in the same shape: `PIN_UNPINNED`, `HISTORY_EMPTY`, `PIN_ATTESTED_EARLIER` (the pin's owner attestation covers an earlier prefix; the positions after it were pinned by writers without the owner key, or a KMS signer has not answered), `ROLLBACK_ACCEPTED`, `ANCHOR_LOG_NONE`, `ANCHOR_LOG_IGNORED`, `ANCHOR_LOG_AFTER_ACCEPTED_ROLLBACK`, and `PIN_MISSING` / `PIN_ATTESTATION_MISSING` when `allowUnpinned` turned them into notes |
| `path`, `format`, `head`, `eventCount` | the file as read |
| `chain` | always `"OK"` when a report is returned; a broken chain throws `INVALID_HISTORY` |
| `pinnedHead?` | the pin as read (`hash`, `position`, `canonicalTime`, `recordHash`, `pinnedAt`, `attestation?`, `rollbackAcceptedAt?`, `previousPin?`) |
| `pinnedHeadStatus` | `MATCHES`, `AHEAD` (normal between pins), `ROLLBACK`, `MALFORMED`, `MISSING` (format 1, events after genesis, no pin) or `UNPINNED` (no pin and none required: legacy, empty or genesis-only) |
| `pinnedAttestation?` | format 1 with a pin: `VERIFIED`, `INVALID` or `MISSING` |
| `attestedHead?` | the head the verified attestation covers (it trails the pin when later writers had no owner key) |
| `rollbackAcceptedAt?`, `previousPin?` | set while the pin still records an accepted rollback |
| `anchors` | `[{ head, anchor, eventId, status: "PREFIX_OK" \| "MISMATCH" }]`, the `ANCHOR_RECORDED` events in the history (`anchor`: their `data.anchor`) |
| `anchorLogStatus` | the anchor logs' verdict (`AnchorLogStatus`): `OK`, `NONE`, `ROLLBACK`, `INVALID`, `UNREADABLE`, `MISSING` or `NOT_APPLICABLE` (legacy) |
| `anchorLogHeads` | every head a consulted anchor log holds (`AnchorLogHead`): `[{ log, location?, head, keyId, receivedAt?, status: "PREFIX_OK" \| "NEWER_THAN_FILE" \| "NOT_A_PREFIX" \| "SIGNATURE_INVALID" }]` |
| `controlSignatures` | `VERIFIED` (format 1) or `NOT_APPLICABLE` (legacy) |
| `remoteWitnessStatus?` | with remote witnesses (§7a): `OK`, `ROLLBACK`, `SPLIT_VIEW`, `INVALID`, `UNREACHABLE`, or `NOT_CONSULTED` (the synchronous `verify()`) |
| `remoteWitnesses?` | `verifyWithWitnesses` only: `[{ url, name, verifierKey, origin?, bound, status, latest?, receiptVerified, consistent, checkpointSize?, unwitnessedTail?, equivocations?, lastEquivocation?: { index, position, receivedAt }, error? }]` (`RemoteWitnessReport`) |

Remote-witness failures (§7a): `REMOTE_WITNESS_ROLLBACK` (a witness's latest head is past the file or not a prefix of it), `REMOTE_WITNESS_SPLIT_VIEW` (a witness could not prove its checkpoint consistent with the one remembered), `REMOTE_WITNESS_INVALID` (an answer that does not verify with the configured verifier key: a bad receipt, note or proof), `REMOTE_WITNESS_UNREACHABLE` (fewer than `n - quorum + 1` witnesses answered; a note instead with `allowUnreachableWitness`, or when enough others answered). Notes: `UNWITNESSED_TAIL n` (the last `n` events are not yet held by a quorum), `REMOTE_WITNESS_UNREGISTERED` (a witness only configured, not bound), `REMOTE_WITNESS_BINDING_WITHOUT_RECEIPT` (a bound witness whose binding carries no REGISTERED receipt: its unsigned "not registered" counts as unreachable; run `witness add` again), `REMOTE_WITNESS_NOT_CONSULTED`, `REMOTE_WITNESS_EQUIVOCATION_RECORDED n` (the witness recorded `n` owner-signed head statements that conflict with heads it holds: the owner key signed a conflicting head; if you did not restore or roll back this history, treat the owner key as compromised and rotate it — `EQUIVOCATION_WARNING`; the file itself is judged by the prefix check, so this is not a failure). The owner forms set `rollback: true` for `REMOTE_WITNESS_ROLLBACK` too.

The rules behind each status are `docs/HISTORY-FORMAT.md` §9–10.
