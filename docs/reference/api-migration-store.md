```js
import { migrateHistory, verifyHistory } from "@ramex-labs/irontrellis/local";
// A Continuity-written source has no pinned head: check it against a copy you trust, then opt in.
const result = await migrateHistory({ source: "./legacy.jsonl", target: "./migrated.jsonl", now: Date.now, acceptUnpinnedSource: true });
// { sourceHead, targetHead, eventCount, ownerKeyId, nextKeyDigests, nextKeyId, nextKeyFile }  — targetHead.position === sourceHead.position
const report = verifyHistory("./migrated.jsonl");
report.ok, report.controlSignatures;                    // true VERIFIED
```

`migrateHistory({ source, target, signer?, ownerKeyReference?, now, acceptUnpinnedSource?, reuseExistingKey?, nextKey?, nextSigner?, nextKeyReference?, nextPublicKey? })` re-records a legacy history as format 1 (`docs/HISTORY-FORMAT.md` §11). The whole target is built and replayed on a private state before a byte is written; the source is untouched. Legacy files are unsigned, so migration would sign an edited or truncated source under the new owner key: by default only a source whose pinned head `MATCHES` the file is migrated, and anything else is `MIGRATION_UNSUPPORTED` with `detail.reason` `SOURCE_UNPINNED` (no pin, which is every Continuity-written file) or `SOURCE_PIN_MISMATCH` (and `detail.pinnedHeadStatus`). `acceptUnpinnedSource: true` migrates such a source anyway; check it by other means first. A fresh `<target>.owner-key.json` is created unless `signer` or `ownerKeyReference` is given; `ownerKeyReference` (a key reference as `keyReference(…)` builds it: ssh-agent, command or Vault Transit) writes only the reference to `<target>.owner-key.json` and signs through that signer (`INVALID_INPUT` with `signer` too; a signer that cannot sign is `KEY_UNAVAILABLE` and the reference is removed again; with `reuseExistingKey` a file already there must name the same key, else `KEY_EXISTS`); a key file already there is `KEY_EXISTS` unless `reuseExistingKey: true`. Like `createLocalOwner`, the target genesis commits the owner key to a next key (`nextKeyDigests`): by default a new Ed25519 key written to `<target>.owner-next-key.json` (0600; move it off the host), or the key `nextSigner`, `nextKeyReference` or `nextPublicKey` names (a signer or reference must prove possession before anything is written); `nextKey: false` migrates without a commitment, and `reuseExistingKey` also adopts a next-key file already there. A refused migration removes the key files it created. `MIGRATION_UNSUPPORTED` also when the source is not legacy or an event cannot be re-recorded; `HISTORY_EXISTS` when the target exists. The migrated history opens with the format-1 domain `{ protocol: "irontrellis", version: "1", deploymentId: <source deploymentId> }`, unlimited capacity, and the same decisions.

`verifyHistory(historyFile, options?)` → `OwnerVerification` (§7) for any history file, no key or profile needed. `VerifyHistoryOptions`:

| option | meaning |
|---|---|
| `allowUnpinned?` | a missing pin or a pin without an owner attestation (format 1) is a note instead of a failure |
| `anchorLogs?` | anchor logs to consult besides `<historyFile>.anchors` (which is always consulted when it exists), e.g. `[localAnchorLog("/mnt/other/history.jsonl.anchors")]`. Each must implement `entries()`; a Rekor anchor cannot and is `INVALID_INPUT` |
| `acceptRollback?` | re-pin a history whose pin is behind, malformed, missing or without a valid owner attestation of a prefix of the file, or whose `<historyFile>.anchors` holds a later head, as the file is now (a write: the pin records `rollbackAcceptedAt` and the previous pin; an unreadable anchor log is reported, not accepted) |
| `signer?` | attests that re-pin (format 1); without it the new pin is unattested, a later `verify` reports `PIN_ATTESTATION_MISSING`, and every reader refuses the file (`PIN_UNATTESTED`) until `repin({ acceptRollback: true })` runs with a signer |

`verifyHistoryWithWitnesses(historyFile, options?)` → `Promise<OwnerVerification>`: the same checks plus the remote witnesses configured in `<historyFile>.witness.json` or bound in the history (§7a). Options: `allowUnpinned?`, `anchorLogs?` as above, `witness?` (a `WitnessPolicy` to use instead of the side file's, or `false` to skip the remote witnesses) and `allowUnreachableWitness?`. Read-only: nothing is written, the side file included.

Without `acceptRollback` it opens the file for inspection only (`inspect: true`), so pin, anchor-log and witness problems are reported in `failures` and never thrown; a file that is not a valid history throws `INVALID_HISTORY`. It opens the file (one full replay, every signature verified) and then re-reads it and re-checks every record hash, chain link and prefix hash against that replay; the history is replayed once, not twice. Decide on `report.ok`: it is `true` exactly when `failures` is empty.

`StoreOptions`:

| option | meaning |
|---|---|
| `acceptRollback?` | when the open finds a rollback (`ROLLBACK_DETECTED`, any reason in §11): re-pin the file as it is (attested when `signer` is set), recording `rollbackAcceptedAt` and the previous pin, instead of throwing. For `ANCHOR_LOG_ROLLBACK` the pin is rewritten only to record the acceptance; the anchor log keeps failing `verify()` and plain opens until it is archived. `ANCHOR_LOG_UNREADABLE` is not accepted |
| `allowUnpinned?` | open (and `verify()`) a format-1 history whose pin is missing or has no valid owner attestation of a prefix of the file (`PIN_MISSING`, `PIN_UNATTESTED`, `PIN_ATTESTATION_INVALID`, `PIN_ATTESTED_NOT_PREFIX`), or whose `<path>.anchors` holds a later head (`ANCHOR_LOG_ROLLBACK`) or cannot be read (`ANCHOR_LOG_UNREADABLE`), instead of failing. Reads only: every write refuses with the problem found. `BEHIND_PIN` and `PIN_MALFORMED` still fail the open |
| `inspect?` | open for verification only: every pin problem (rollback, missing, malformed, attestation) and the anchor log are left for `verify()` to report instead of thrown, and every write, including `acceptRollback`'s re-pin, is refused (`READ_UNAVAILABLE`) |
| `reuseExistingKey?` | `createHistoryStore` only: use an owner key file already at `<path>.owner-key.json` instead of refusing with `KEY_EXISTS` |
| `lockTimeoutMs?` | wait up to this long for another writer's lock before `STORE_BUSY` (default 0: fail at once) |
| `signer?` | attests every pinned head (format 1) |
| `hooks?` | `ReplayHooks`, for tests |
| `fsync?` | default `true`: fsync file, directory and pin after each write |
| `now?` | clock for `pinnedAt` and the lock |
| `retry?` | `{ attempts?: 3, delayMs?: 10 }`: re-reads when the pin is momentarily ahead of the file, or still absent after a history's first write |
| `witness?` | `WitnessPolicy \| false` (§7a): default the side file's policy plus the history's bindings; a policy given here replaces the side file's (bindings still apply) and, on `createHistoryStore`, is written to the side file. `false` turns remote witnesses off for this handle |

`HistoryStore`: `path`, `format` (`undefined` for an empty or absent file), `state()` (`HISTORY_EMPTY` engine error on an empty store, `INVALID_HISTORY` on a defective file), `head()`, `readAll()`, `append(event)` (CAS against the current head under the lock), `appendAtExpectedHead(event, expected)` (`StoreConflictError` / `STORE_CONFLICT` otherwise), `appendAll(events)` (genesis creation on an empty store; the batch is validated before any byte is written), `withExclusiveWriter(cb)` (the `EventStore` contract the coordinators use; an async callback keeps the lock until it settles; a lock held by another process is `STORE_BUSY` with `detail.lockPath` and, when readable, `detail.holder` `{ pid, hostname, createdAt }`), `verify(options?)` (re-reads the file and re-checks every record hash, chain link and prefix hash; when the bytes match the cached replay — same size, last line and record hashes — that replay stands in for a second one, otherwise the file is replayed again; then judges the pin, its attestation, the recorded anchors and the witnesses and returns a `VerificationReport`, §7; `options` = `{ allowUnpinned?, anchorLogs? }` as for `verifyHistory`), `pinnedHead()` (the pin file as read; `ROLLBACK_DETECTED` with reason `PIN_MALFORMED` for an unparsable one), `repin(options?)` (re-pins the current head under the writer lock, attested by the configured `signer`, to bring the owner's attestation up to the head after writers without the owner key (`PIN_ATTESTED_EARLIER`) or after a KMS signer could not answer. Format 1 needs a signer (`KEY_UNAVAILABLE` otherwise). It re-judges the pin and the anchor logs under the lock and refuses with `REPIN_REFUSED` (an engine error; `detail.reason` is `BEHIND_PIN`, `PIN_MALFORMED`, `PIN_MISSING`, `PIN_UNATTESTED`, `PIN_ATTESTATION_INVALID`, `PIN_ATTESTED_NOT_PREFIX`, `ANCHOR_LOG_ROLLBACK` or `ANCHOR_LOG_UNREADABLE`, with the finding's other detail fields) instead of attesting a file that may have been cut back. `options` = `{ acceptRollback?, anchorLogs? }` (`RepinOptions`): `acceptRollback` (default: the store's option) re-pins anyway and records `rollbackAcceptedAt` and the previous pin (not for `ANCHOR_LOG_UNREADABLE`); `anchorLogs` are consulted besides `<path>.anchors`. A pin that already attests the current head is returned unchanged. Open the store with `allowUnpinned` to call it on a history whose open would refuse), `flush()` (resolves when asynchronous head attestations from a KMS signer have been written, and, with remote witnesses, when a quorum of them holds the current head; rejects once with the signer's or the pin write's failure, or with the witness finding), `attestationsSettled()` (resolves once the head attestations and witness-cache seals an asynchronous signer owes have been written or have failed; never rejects, no network; the attestation re-reads and rewrites the pin under the writer lock), `checkWitnesses(options?)`, `witnessStatus()`, `verifyWithWitnesses(options?)` (§7a), `close()` (drops the cached history; every later call fails with `READ_UNAVAILABLE`; idempotent; does not wait for pending attestations). `createHistoryStore(path, genesisEvents, options)` creates the file exclusively (mode 0600) and writes the batch; `HISTORY_EXISTS` if present. Give it the owner `signer` for a format-1 batch of more than the genesis: without one the first pin is unattested, and every later open refuses the history (`PIN_UNATTESTED`) until it is re-pinned with `acceptRollback` and a signer. For a format-1 genesis, an owner key file already at `<path>.owner-key.json` is refused with `KEY_EXISTS` (`detail.keyPath`) unless `reuseExistingKey`: a leftover or planted key is never adopted silently. A file that cannot be created or opened for writing is `READ_UNAVAILABLE` with `detail.mayHaveCommitted: false` (nothing was written); `WRITE_UNCONFIRMED` is kept for failures after the write began. `HISTORY_FILE_LIMITS` (also exported from the root) is the per-format size limit in bytes: `{ "continuity-event/0.2": 67108864, "irontrellis-event/1": 1073741824 }`. An append that would pass it is `HISTORY_FILE_LIMIT`; a larger file is refused on open. The reader decodes the file line by line, so the whole format-1 limit is readable. Events handed to the store must already carry their `controlAuthorization` in format 1 (`signControlEvent`); the store validates, it does not sign.
