## 14. Format 2: `RECONCILIATION_OBSERVED` (type 42)

Format 2 (`irontrellis-event/2`) is defined by the format-2 specification and its addenda, not by this page. This section records one format-2 event type in plain terms, because outside tools that reconcile a provider's event log write it.

A reconciler is an agent with an admitted runtime session. It reads a provider's event stream (for example a payment provider's webhook log) and records, for each provider event, one signed claim: whether the event matches a decision in this history. Only a SHA-256 digest of the provider event enters the history, never the event itself.

* **Type and code.** `RECONCILIATION_OBSERVED`, projection type code 42. Code 41 is not assigned. A legacy or format-1 history that carries the type is `UNSUPPORTED_EVENT_TYPE`; inside a migrated prefix it is `EVENT_DATA_INVALID`.
* **`data`** (closed): `observationId`, `reconcilerAgentId`, `source: {streamId, eventRef, eventDigest}`, `call: {actorId, action?, resource?, observedAt?, amount?, unsupplied}`, `match: {result: "MATCHED" | "UNMATCHED", position?}`, `expectedHistoryHead` (the full head before the event), `runtimeSessionId`, `credentialKeyId`, `controlEpoch`, `observationAuthorization: {hash, signature}`. `call.unsupplied` lists, in byte order, which of `action`, `observedAt` and `resource` the provider did not supply; each of the three is absent exactly when it is listed. `call.resource` is a string of at most 128 characters, counted as Unicode code points. `match.position` is present exactly when the result is `MATCHED`. There is no `controlAuthorization`: an owner key never signs an observation.
* **Signature.** The session signs `hashCanonical` of `{version: "irontrellis-reconciliation-authorization/2", domain, eventId, eventType: "RECONCILIATION_OBSERVED", timestamp, observationId, reconcilerAgentId, source, call, match, eventHistoryHash, eventHistoryPosition, runtimeSessionId, credentialKeyId, controlEpoch}`, with `source`, `call` and `match` exactly as written and the head fields taken from `expectedHistoryHead`.
* **Replay, in order.** The schema (`EVENT_DATA_INVALID`; a missing or malformed `observationAuthorization` counts here). The session checks: a session of an earlier control epoch is `SESSION_FENCED`; every other session failure, a wrong `hash` or a signature that does not verify is `OBSERVATION_AUTHORIZATION_INVALID`. Then, each `TRANSITION_INVALID`: `reconcilerAgentId` is the signing session's agent; `expectedHistoryHead` is the head just before the event; for `MATCHED`, `match.position` is earlier and holds a `TRANSACTION_INTENT_ADMITTED` or `REQUEST_REFUSED` whose actor is `call.actorId`. Then duplicates: if any accepted observation has the same `(streamId, eventRef, eventDigest)`, the event is `OBSERVATION_DUPLICATE`. If the same `(streamId, eventRef)` was seen only with other digests, the event is accepted and records `equivocates`, the position of the earliest observation of that pair. The index covers the whole history, across reconcilers. Then `observationId` must be new (`TRANSITION_INVALID`). Last comes capacity: the type is growth, so it is refused with `CAPACITY_CONTROL_ONLY` at `maxEvents`.
* **State records.** `observation` (key `observationId`): `{observationId, reconcilerAgentId, source, call, match, equivocates, eventId, position}`. `reconciliation-cursor` (key `hashCanonical([reconcilerAgentId, streamId])`): `{reconcilerAgentId, streamId, lastEventRef, lastPosition, count}`, created with `count` 1 by the pair's first observation. With the `event` record, the first observation of a pair adds three records and each later one adds two.
* **Projection row.** Actor `reconcilerAgentId`, subject `call.actorId`, amount `call.amount` when present. Flag bit 1 is set (session-signed) and bit 2 is set when `call.amount` is present.

An observation is one session's signed claim about one provider event. It does not prove that the provider sent every event or that any external effect happened. When the same provider event is recorded with two digests, the history shows that the story changed, not which version is true. `verify` lists such equivocations, `MATCHED` observations whose call differs from the cited request, and observations a reconciler made about its own calls.
