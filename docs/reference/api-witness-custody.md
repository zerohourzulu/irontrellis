**Policy** (`WitnessPolicy`, stored in the side file without its transports):

| field | default | meaning |
|---|---|---|
| `witnesses` | — | `[{ url, verifierKey, name?, timeoutMs? (10 000), token?, fetch? }]` (`RemoteWitnessConfig`), 1..16, deduplicated by verifier key. `verifierKey` is the witness's note verifier key, the only trust anchor: every checkpoint and receipt must verify with it. `token` is the registration token of a witness that requires one |
| `quorum` | 1 | a head counts as witnessed once this many witnesses hold it (also signed into the binding as the policy minimum, counted over the bound witnesses; see **Witness bindings** below). Rollback or split-view evidence from ANY single witness is fatal whatever the quorum (an `EQUIVOCATION` answer to this handle's statement is rollback evidence). Every check (first write, `requireOnOpen`, verification, and each submission round before anything is signed) needs answers from `n - quorum + 1` witnesses, so it meets one of any `quorum` witnesses that accepted the latest head: with 3 witnesses, quorum 2 tolerates one witness down, quorum 1 tolerates none |
| `mode` | `async` | `sync`: an owner write submits its head statement before it returns (an unreachable witness leaves it queued; rollback evidence throws `ROLLBACK_DETECTED` after the event was appended locally). `async`: a background worker (unref'd timers, exponential backoff with jitter, capped at 30 s, 20 attempts until the next write or `flush()`) submits only the newest head (statements chain by `previous`) |
| `maxUnwitnessedEvents` | 1000 | an owner-keyed writer refuses to append (`WITNESS_UNAVAILABLE`, `detail.reason: "MAX_UNWITNESSED"`) while this many events are not held by a quorum; reads continue. Writers without the owner key sign no statements and are not limited; the next owner-keyed write covers their events |
| `requireOnOpen` | false | readers confirm with the witnesses before they read: reads throw `WITNESS_UNAVAILABLE` (`detail.reason: "NOT_CHECKED"`) until `checkWitnesses()` succeeds (the CLI, hooks and gateway call it). Owner-keyed writers always ask before their first write in a process |
| `cacheMs` | 60 000 | how long a `requireOnOpen` reader may rely on an earlier answer instead of asking: one this process verified (any handle), or one an owner-keyed process sealed with the owner key in the side file (an unsealed or forged cached answer never counts). A cache only skips a network call, never overrides a failure; writers never take the side file's word |
| `fetch` | `globalThis.fetch` | transport for every witness that sets none |

**Client**: `remoteWitness(config, { tracker?, fetch? })` → `RemoteWitness` with `info()`, `checkpoint()`, `register(genesis)`, `history(historyId)`, `submit(signedStatement)`, `keyEvent(historyId, { event, previousHead, eventHead, statement?, chain? })`, `head(historyId, position)`, `consistency(from, to)`, `entries(start, end)` over the `irontrellis-witness/1` HTTP contract (`docs/WITNESS.md` §9.6). Every request about a history carries a fresh random `nonce` (`newNonce()`, 32 bytes) and every answer must carry the witness's `latestNote` signed over it, naming exactly the answer's `latest` (head, leaf index, tree size), equivocation count and supersede count (`docs/WITNESS.md` §9.8), else `WITNESS_INVALID_RESPONSE` (`detail.reason` `LATEST_NOTE_MISSING` / `LATEST_NOTE_INVALID` / `LATEST_NOTE_MISMATCH`): a replayed older answer cannot pass. `register()` also returns the note's `latest` (`{ hash, position } | null`). Every checkpoint in a response is verified with the configured key and checked for consistency with the largest checkpoint seen in this process and the one the `tracker` remembers (`CheckpointTracker`: `{ get(origin), set(origin, checkpoint) }`; the store's persists it in the side file; default memory): a larger tree must come with a valid consistency proof, a smaller one must be proven a prefix of the remembered one, an equal size must have the same root. Failing that is `WITNESS_SPLIT_VIEW`, sticky for the client. Every receipt is verified with `verifyWitnessReceipt` against the configured key and must name the expected entry (the REGISTERED entry of this genesis, the HEAD entry of this statement or head, the ROTATED entry of this key event, the SUPERSEDED entry of this rotation and chain, the EQUIVOCATION entry of this history), else `WITNESS_INVALID_RESPONSE`. Transport failures, timeouts (an `AbortSignal` per request), 5xx, 408 and 429 are `WITNESS_UNAVAILABLE`; other refusals `WITNESS_REJECTED` (`detail.code`, `detail.hint`). `STALE_PREVIOUS`, `EQUIVOCATION` (with `latest`; its receipt must be a verifiable EQUIVOCATION leaf of this history, else `WITNESS_INVALID_RESPONSE`; `evidence` says what it proves: `SUBMITTED` records this very statement, `POSITION` another conflicting statement at the same position (the witness keeps one entry per position), `OTHER` the history's most recent entry past the 64-per-history cap, which proves nothing about this position, so the fresh signed `latest` decides) and `NOT_REGISTERED` come back as results; `history()` returns `equivocations` and the verified `lastEquivocation`, `supersedes` and the verified `lastSupersede`, and the epochs with their `nextKeyDigests`. `keyEvent()` returns `ACCEPTED` (`receipt`, `index`, `epochs`, `latest`, `superseded?`), `STALE_PREVIOUS` (`latest`), `NOT_REGISTERED` or `REJECTED` (`code`, `message`, `status`, `hint?`); `submit()` returns `SUPERSEDED` (with `latest`) for a statement that states or extends a superseded head. `signStatement(signer, state, previous)` signs the statement for the state's head after checking rule W2 (`previous` is null or a prefix, the key is in force at the head); `verifySignedStatement(signed, state)`. `normalizeWitnessPolicy`, `normalizeWitnessConfig`, `witnessesToConsult(policy)` (`n - quorum + 1`) validate and explain a policy.

**What the store and owner do** (format 1; `openHistoryStore`, `openLocalOwner`, every runtime handle, the CLI, the hooks and the gateway alike):

* *Create*: `createLocalOwner({ witness })` registers the genesis with every witness before the file exists (a refusal, another key or an invalid answer fails the creation with `WITNESS_REJECTED` and writes nothing, not even the key file; an unreachable witness is registered by the first submission), then writes the genesis, the principal and the binding (`WITNESSES_BOUND` at position 2, carrying each witness's signed REGISTERED receipt) together, so no pinned copy exists without the binding, and writes the policy to the side file. The witnesses of the out-of-band minimum policy are registered and bound too. `createHistoryStore(path, genesis, { witness })` only writes the policy.
* *Out-of-band minimum*: `IRONTRELLIS_WITNESS_POLICY=<absolute path>` names a JSON `WitnessPolicy` that every store open merges in as a minimum (it adds witnesses, raises `quorum`, `mode`, `requireOnOpen`, lowers `maxUnwitnessedEvents`, `cacheMs`; absent fields constrain nothing). An unusable file fails the open (`WITNESS_UNREADABLE`, `detail.reason: "WITNESS_POLICY_UNREADABLE"`). `witness: false` opens without it. `minimumWitnessPolicy(env?)`, `WITNESS_POLICY_ENV` (`docs/WITNESS.md` §5.4).
* *Registration refused, registration denied*: a 4xx answer to the registration (`UNAUTHORIZED`, `INVALID_GENESIS`, `UNSUPPORTED_FORMAT`, …) puts that witness into a sticky `WITNESS_REJECTED` state (`detail.reason: "REGISTRATION_REFUSED"`): owner-keyed writes refuse at once until the policy for that witness changes (503 `HISTORY_LIMIT_REACHED` stays transient). A "not registered" answer from a witness the history binds with its signed REGISTERED receipt is a denial of its own signature (`boundRegistrationOf(state, verifierKey)` finds the receipt): never answered by registering again; checks fail (`WITNESS_INVALID_RESPONSE`, `detail.reason: "REGISTRATION_DENIED"`: the `requireOnOpen` gate stays closed, owner writes refuse) and verification reports `REMOTE_WITNESS_INVALID`.
* *Before the first owner-keyed write of a process*: every witness is asked for its latest head (network, never the side file). A latest head that is not a prefix of the file puts the handle into a sticky alarm: this and every later read and write throws `ROLLBACK_DETECTED` with `detail.reason` `WITNESS_AHEAD` (past the file) or `WITNESS_FORK` (a different head there), and nothing is signed for that copy. Unreachable witnesses do not stop the write: its statement waits for a verified answer. An answer that does not verify is not unreachability: when too few witnesses gave a verifiable answer and one of them gave an invalid one, the write is refused with `WITNESS_UNAVAILABLE`, `detail.reason: "INVALID_ANSWER"`, `detail.cause: "WITNESS_INVALID_RESPONSE"` (nothing appended; the next write asks again), and `checkWitnesses()` rejects the same way (the `requireOnOpen` gate stays closed).
* *After each owner-keyed write*: the head is queued (a coalesced marker in the side file); `sync` submits now, `async` wakes the worker. Each submission round first asks every witness again, then, holding the store's writer lock, decides what to send and signs the statement for the current head with `previous` = the witness's latest (rule W2: only after it was found to be a prefix of the state read under that lock), signed by the key in force at that head; the network calls happen after the lock is released. The state under the lock must still contain the head this handle appended (or last verified under the lock): a file swapped behind the writer is `ROLLBACK_DETECTED`, `detail.reason: "FILE_CHANGED_UNDER_WRITER"` (sticky; nothing is signed; `docs/WITNESS.md` §2.3). `STALE_PREVIOUS` with a prefix → signed again with the new `previous`; not a prefix → the alarm. `EQUIVOCATION` (the witness holds another head at the statement's position; it records the statement as evidence and stays open, `docs/WITNESS.md` §9.2) → the same alarm, reason `WITNESS_FORK` (`detail.equivocationIndex`): this handle's file is not on the witness chain and the handle never signs again. Restore a copy that is on the chain and write on: the witness accepts statements that extend its latest head.
* *Rotation* (`docs/WITNESS.md` §7): with bound witnesses, two-phase (above): the witnesses record the old-key statement for the rotation head `r` and the rotation before it is appended. Local-first (`emergency`, `commitOwnerKeyRotation`, or no bound witness): right after the rotation is appended and before the key files are swapped, the statement for `r` is signed with the old key (for every witness whose latest this process verified) and queued with the rotation (`previousHead` = head `r - 1`, `rotationHead` = head `r`) in the side file, and submitted to every witness before `rotateOwnerKey` returns, in `async` mode too; for a witness it could not reach the queue keeps them first. A witness answering `SIGNATURE_INVALID` with hint `ROTATION_REQUIRED` gets the pending rotations first. A crash before the queue reached the side file is recovered by signing statement `r` with the archived key file `<history>.owner-key.<id>.retired.json`.
* *Key events*: every rotation the history holds and a witness lacks (commitment-only rotations included) is delivered (`keyEvent`, with the statement for its head in the same request when the witness does not hold that head yet), before later statements. A witness learns epoch 0's commitment from the genesis it registered.
* *Supersede* (`docs/WITNESS.md` §7.4): when a witness's latest is not a prefix of the file (`STALE_PREVIOUS`, `EQUIVOCATION`, or a check), and the history holds a rotation that witness lacks, the client supersedes instead of raising the alarm if that rotation is pre-rotated: L is the newest head this process verified the witness held on its chain, or the witness-signed `held` receipt in the side file (verified, and a prefix of the file); the chain statement (head `r`, `previous` = L) is signed under the writer lock with the key in force at `r` (the retired key file when needed). Not pre-rotated, L unknown, the key missing, or a refusal: the alarm, with the reason in the message and `detail.supersede`. `verify` reports `REMOTE_WITNESS_SUPERSEDED n` (a note; the CLI prints a WARNING, `SUPERSEDE_WARNING`).
* *Prepared rotation*: a witness holding the head of an outstanding prepared rotation is not a rollback: the next owner command appends the prepared event (above); `verify` notes `REMOTE_WITNESS_ROTATION_PENDING`. `REMOTE_WITNESS_ROTATION_INCOMPLETE` notes a bound witness lacking a rotation, `NO_NEXT_KEY_COMMITMENT` owner keys in force without a commitment (`NO_COMMITMENT_WARNING`).
* *Every read and write*: what this process learned (shared by all handles of the process) must stay a prefix of the file, however it changes underneath; a head the side file remembers that the file lacks, or a recorded split view, refuses reads and writes like a local anchor log holding a later head does.
* `witnessStatus()` → `WitnessStatusReport` `{ statePath, historyId?, policy, bound, boundPolicy? (the owner-signed policy minimum in force), alarm?, rejected?, minimumPolicyFile?, keyRotations (`OWNER_KEYS_ROTATED` events that changed the owner keys), commitmentRotations (commitment-only rotations that kept them), rotationIncomplete (a bound witness this process asked lacks a rotation, or one is still queued), rotationPending? ({ position, hash, eventId } of an outstanding prepared rotation), checkRequired, ownerKeyed, head?, witnessedPosition, unwitnessedEvents, pending, witnesses: [{ url, name, verifierKey, origin?, bound, registered, latest?, source: "network" | "sealed-cache" | "unsealed-cache" | "none", knownAt?, equivocations? (the count the witness reported when this process last asked it), pendingRotations (owner key rotations, commitment-only ones included, the witness has not recorded, as last learned; `null` when not asked), supersedes?, rejected?, registrationDenied?, bindingWithoutReceipt? (bound without a REGISTERED receipt), checkpointSize?, splitView?, lastError? }] }`, without network.
* *Witness URLs*: `https:`, or plain `http:` only to a loopback host (`isLoopbackHost`: `localhost`, `127.0.0.0/8`, `[::1]`) or with `allowInsecureHttp: true` in the witness config; otherwise `INVALID_INPUT` (`detail.reason: "INSECURE_HTTP"`): answers are signed (freshness included), but plain HTTP exposes the traffic and the registration token (`docs/WITNESS.md` §4.3).
* *Retired key files* are found by key, not by name: every `<history>.owner-key.*.retired.json` (`retiredOwnerKeyFilesFor(historyFile)`, clash suffixes `-2`, `-3` … included) is loaded and used only when its key id and public key match a key in force at the head to sign.
* `openLocalOwner({ …, witnessRecovery: true })` opens a copy that a remote witness shows rolled back (or a split view) instead of failing: every read and write still refuses; it is the handle for `removeWitness(…, { acceptRemoteLoss })`.

**Witness bindings**: the owner-signed control events `WITNESSES_BOUND` `{ witnesses: [{ url, verifierKey, name?, allowInsecureHttp?, registration? }], policy: { quorum, requireOnOpen, maxUnwitnessedEvents } }` and `WITNESSES_UNBOUND` `{ verifierKeys, policy, acceptedLoss?: { reason, heads: [{ verifierKey, head }] } }` (`docs/HISTORY-FORMAT.md` §10.1; `registration`: the witness's signed receipt of the REGISTERED leaf of this history; `policy`: the owner-signed policy minimum after the event). Replay keeps `state.boundWitnesses` and `state.boundPolicy`. The witnesses the history binds stay in force whatever the side file says: deleting or editing `<history>.witness.json` cannot remove them, and a copy of the history keeps them from the binding on. A bound witness is **pinned**: its URL, verifier key and `allowInsecureHttp` come from the binding only (the side file may add a token and a name, a caller's `witness` option a timeout and a transport); moving it takes `addWitness` with the new URL for the same verifier key (a new `WITNESSES_BOUND` re-binds it in place). The **policy minimum** of the newest binding event (`boundPolicyOf(state)`) is merged as the strictest with every other source (the higher quorum, `requireOnOpen` if any says so, the lower `maxUnwitnessedEvents`); `addWitness(config, update)` signs `update`'s `quorum` / `requireOnOpen` / `maxUnwitnessedEvents` into its binding (`bindingPolicyOf(policy, boundCount)`), `removeWitness` signs the remaining witnesses' minimum. Every check needs `bound − quorum + 1` answers from the bound witnesses themselves; witnesses only the side file names add findings but never answer for a bound one (`docs/WITNESS.md` §5.3). `boundWitnessesOf(state)` lists them, `boundRegistrationOf(state, verifierKey)` gives one's verified registration, and `witnessBindingEvent(...)` builds a binding event. An `ANCHOR_RECORDED` never binds anything, whatever its receipt holds.

**Side file** `<history>.witness.json` (0600, written atomically under `<history>.witness.json.lock`): `{ version: "irontrellis-witness-state/1", historyId, policy, witnesses: { [origin]: { url, verifierKey, registered, checkpoint?: { size, rootB64, note }, latest?: { head | null, fetchedAt, seal?: { keyId, scheme, signature } }, splitView?: { detectedAt, message }, rejected?: { code, message, detectedAt, config } } }, pending: [ { kind: "statement", head, statements?: { [origin]: signedStatement } } | { kind: "rotation", rotation, previousHead, rotationHead } ] }`. It is writable by whoever can write the history and may only ever make things stricter: the witnesses are the authority. A deleted or rolled-back side file loses split-view detection strength and queued items (all re-derivable from the history and the witnesses, the old-key rotation statement from the archived key file), never a rollback check; a file that cannot be parsed fails the open (`WITNESS_UNREADABLE`, `detail.reason: "WITNESS_STATE_UNREADABLE"`). `seal` is an owner signature over `hashCanonical({ version: "irontrellis-witness-cache/1", historyId, origin, verifierKey, url, head, fetchedAt })`: it names the one witness it was made for (`sealCachedLatest(signer, { historyId, origin, verifierKey, url }, head, fetchedAt)`, `cachedLatestIsSealed(state, witness, cached)`). Seals are written and accepted only for bound witnesses (origin from the binding's verified REGISTERED receipt; none for a binding without one) and those of the out-of-band minimum. `witnessStatePathFor(historyFile)`, `readWitnessState(path)`.

Residual limits: a restored copy from before the first binding names no witness (a history created with `witness` has none), so only a reader configured with the witness out of band (the `IRONTRELLIS_WITNESS_POLICY` minimum, the `witness` option, `irontrellis verify` with the side file present) detects it; a `requireOnOpen` reader accepts an owner-sealed answer up to `cacheMs` old; a stolen owner key can sign statements (the witness log makes them public, conflicting ones are recorded as capped `EQUIVOCATION` evidence; rotate the key), and a witness that has not recorded a rotation still accepts heads signed by the retired key (`witnessStatus().witnesses[].pendingRotations`); a malicious witness can show different logs to different clients (each client detects it against its own remembered checkpoint; several witnesses with a quorum narrow it further). A witness that has not recorded a rotation (unreachable at rotation time, or added later) needs the statement for the rotation head signed by the retired key, which the client loads from an archived `<history>.owner-key.*.retired.json` holding that key (`KEY_UNAVAILABLE` without it). `acceptRollback` does not accept a remote-witness finding, and `removeWitness` is refused like any write while one stands, except as the owner-signed `acceptRemoteLoss` decision. See `docs/WITNESS.md` §3, §6.2 and §7.

* `Signer` has an optional `custody: { holder: "file" | "reference" | "public-key-only", signer?, description, identity?, path? }` (set by the key-file loaders and `referenceSigner`), and `signHash(hash, context?)` takes an optional advisory `SignContext` = `{ purpose?: SignPurpose, historyId? }` (`SIGN_PURPOSES`: `control-authorization`, `head-attestation`, `head-statement`, `next-key-proof`, `rotation-seal`, `cache-seal`, `signer-test`). A signer may ignore it.
* `OwnerKeyReference` = `{ version: OWNER_KEY_REF_VERSION | OWNER_NEXT_KEY_REF_VERSION, keyId, scheme: "ed25519", publicKey, signer: { kind, … }, comment? }` (docs/HISTORY-FORMAT.md §13.1). `keyReference({ keyId, publicKey, signer, next?, comment? })` builds one (checked; `publicKey` in any accepted spelling), `parseKeyReference(json, where?)` checks one (`KEY_UNAVAILABLE` on a defect), `keyReferenceText(ref)`, `withReferenceVersion(ref, version, keyId?)`, `writeKeyReferenceFile(path, ref)` (0600, exclusive, `KEY_EXISTS`; returns its signer), `keyFileHolder(path, "owner" | "next")`, `readKeyReferenceFile(path, "owner" | "next" | "any")` (a reference with the loaders' checks: no symbolic link, 0600, owned by this user), `inspectKeyFile(path, kind)` (`{ reference }` or key material, loader checks, no signer contacted). Every loader refuses a symbolic link (`O_NOFOLLOW`, reason `SYMLINK`).
* `loadOwnerKeyFile` / `loadNextOwnerKeyFile` return a reference's signer for a reference file (no signer is contacted by a load; POSIX: 0600 and owned by the loading user). `referenceSigner(ref, path?)`: a `Signer` without `signHashSync` that asks the backend and verifies every answer against `publicKey` (`SIGNER_FAILED`, `detail.reason: "SIGNATURE_INVALID"`, never returned otherwise). `publicKeySigner(publicKey, keyId)`: a key known by its public key only (its `signHash` is `KEY_UNAVAILABLE`, reason `PUBLIC_KEY_ONLY`).
* `parsePublicKey(text)` (`0x` + 64 hex, 64 hex, or `ssh-ed25519 AAAA…`; FIDO and other key types are `INVALID_INPUT` with the reason) → `0x` form; `sshPublicKeyOf(publicKey, comment?)`, `parseSshPublicKey(line)`, `sshPublicKeyLine(bytes, comment?)`, `openSshPrivateKey(seed, publicKey, comment?)` (an unencrypted `openssh-key-v1` file, for `signer to-ssh`).
* Backends: `registerSignerBackend(backend)`, `signerBackend(kind)`, `signerBackendKinds()`; `SignerBackend` = `{ kind, parse(spec), describe(spec), identity(spec), sign(spec, key, message, context) → Promise<Uint8Array> }` (docs/CUSTODY.md §13). Built in: `ssh-agent` (`agentSocketPath(spec, env?, platform?)`, `listAgentIdentities({ socket?, timeoutMs? })`, `WINDOWS_AGENT_PIPE`, `DEFAULT_AGENT_TIMEOUT_MS` = 60 000) `command` (`SIGN_REQUEST_VERSION` = `"irontrellis-sign-request/1"`, `DEFAULT_COMMAND_TIMEOUT_MS` = 30 000, `COMMAND_SIGNER_PATH` = `"/usr/bin:/bin"`, `stderrTail(buffer)`; the reference may set `path`) and `vault-transit` (HashiCorp Vault Transit, docs/CUSTODY.md §7: `{ kind, address, mount? = DEFAULT_VAULT_MOUNT ("transit"), key, keyVersion, namespace?, tokenFile?, caFile?, timeoutMs? }`, `DEFAULT_VAULT_TIMEOUT_MS` = 30 000; `normalizeVaultAddress(url)` (https, or http to a loopback host); `readVaultKey(spec, env?)` → `VaultKeyInfo` `{ name, type, derived, latestVersion, minEncryptionVersion, publicKeys: Map<version, 0x key> }` (a key read, no signature; `keyVersion` may be absent); `checkVaultKey(spec, { keyId, publicKey }, env?)` → `{ ok, code?, reason?, message }` (never throws: doctor's non-signing check); `vaultTokenSource(spec, env?)` → `{ source: "tokenFile" | "VAULT_TOKEN" | "vault-token-file", path? }` (never the token); `vaultCaFile(spec, env?)`). Its `identity` is the address, namespace and token source: two keys one token can sign with are one holder (`NEXT_KEY_SAME_SIGNER`).
* Owner API: `ownerKeyReference`, `nextKeyReference`, `nextPublicKey` (§1), `commitNextKey({ nextPublicKey?, nextKeyReference? })`, `rotateOwnerKey({ nextKeyFile: <a next-key reference>, newNextPublicKey?, newNextKeyReference? })` (a pre-rotated rotation onto a referenced next key promotes the reference: the key stays in its signer). `verifyHistoryAsync(historyFile, options)`: `verifyHistory` that waits for an asynchronous signer's re-pin attestation (`acceptRollback`) before the report.
* Every owner write waits for the pin attestation (and witness-cache seals) of an asynchronous signer before it returns; `signControl` failures keep their code and detail: `KEY_UNAVAILABLE` (the signer does not hold the key) and `SIGNER_FAILED` (anything else), nothing appended. `signerFailure(error)` is the mapping.
* The CLI's `irontrellis doctor` (a read-only custody and deployment audit, docs/CUSTODY.md §11) is not a library API; its pure checks are exported from the CLI package's `dist/doctor.js` for tests only.
* Test mode: `IRONTRELLIS_TEST_ASYNC_SIGNERS=1` (`ASYNC_SIGNERS_TEST_ENV`, never in production) strips `signHashSync` from every signer built from local key material; `pnpm test:async-signers` runs the owner, rotation, two-phase and witness suites (core, witness, CLI, hooks) under it.
