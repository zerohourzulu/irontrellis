`capacityOf(state)` → `CapacityReport` = `{ profile: "irontrellis-capacity/1" | "continuity-managed-capacity/1", eventCount, maxEvents: number | null, mode: "OPEN" | "CONTROL_ONLY", canDeclareJob, lifecycleReserved, declaredJobs, remainingPhysicalEvents, controlAlwaysAdmitted: true, pointInTimeOnly: true, grantsAuthority: false }`. Legacy histories have `maxEvents` 96 (the Core 0.3 profile, minus its control reservation); format 1 uses the genesis budget or `null`. Format 2 also bounds state records: past the reserve an ordinary event is `CAPACITY_RESERVED`, and at `maxStateRecords` every event is `CAPACITY_EXCEEDED`. A declared job reserves one slot per lifecycle record type it has not yet produced. `assertCapacityTransition(state, events)` throws `CAPACITY_CONTROL_ONLY` (or `CAPACITY_EVENT_LIMIT` for a legacy event over 8 KiB / 32 array members / depth 16). Capacity is a point-in-time observation; it never grants authority.

## 9. Additional policy

`AdditionalPolicy` = `{ identity: Id, evaluate(request, signal) → PolicyDecision | Promise, record(evidence) → void | Promise }`. When given to an execution handle, both the history and the policy must allow a new effect. `PolicyRequest` carries `identity, requestHash (keccak-256), domain, actor, action, resource, session, epoch, role, tenure, operationId, termsCommitment, historyHead, amount?, counterparty?`; a decision is `{ identity, requestHash, decision: "ALLOW" | "DENY" | "ERROR", diagnostics: string[] (≤ 32 × 256) }`. The evaluator is bounded to five seconds and any failure becomes `ERROR` with `POLICY_UNAVAILABLE_OR_INVALID`; a failing `record` is `POLICY_EVIDENCE_UNAVAILABLE`. `capturePolicy` and `evaluatePolicy` are exported for tests.

Receipt bounds. The receipt operations keep the reference's history-occurrence bound for **legacy histories only**: a verification whose issuance and observed histories hold more than 4,096 events together is `INDETERMINATE / INVALID_INPUT` (so `createReceipt` over more than 2,048 legacy events fails its self-check), and a record proposal is `INDETERMINATE / OUTPUT_LIMIT_EXCEEDED` from 2,048 legacy events. The portable `verifyReceipt` applies the bound unless every non-empty history it is given declares format 1, so a format-2 receipt passed with its whole history twice fails past 2,048 events. Every receipt operation also captures its event arrays with a 4,096-member bound, so a history of more than 4,096 events cannot be passed whole in any format; the `*State` forms take replayed state instead. Within those bounds, every receipt axis cites only the genesis, the head and the events relevant to the receipt, under the 4,096-reference evidence budget.

The `ReplayState` handed out is the engine's live object (members: `events`, `eventHistoryHashes`, `eventPositionsById`, `head`, `genesis`, `principals`, `agents`, `roles`, `tenures`, `runtimeSessions`, `authorities`, `recognizedRoots`, `authorityUsage`, `intentDeclarations`, `intentAdmissions`, `intentConsumptions`, `intentOutcomeStates`, `receiptCommitments`, `obligations`, `attemptDuties`, `anchors`, …). Read it; never mutate it. `events` and `eventHistoryHashes` are arrays in position order; the iteration order of every Map and Set, `recordRefs` included, is unspecified (A-188.2: identity is the record set, so sort by key where an order is needed).

* **`IronTrellisError`** (`@ramex-labs/irontrellis/local`; `ContinuityError` is a deprecated alias) is what the local API throws: `{ code, mayHaveCommitted, message, detail? }`. `mayHaveCommitted: true` means an I/O failure may have left bytes behind — inspect the file (`verify`) before retrying. `detail` is optional machine-readable context, set for some codes (see below).
* **`EngineError`** (`{ code, detail }`) is thrown by the engine and store layers when used directly (`openHistoryStore`, `anchorHead`, `signControlEvent`, …). The owner API translates engine codes into the table below; `STORE_CONFLICT` / `STORE_BUSY` become `HISTORY_CONFLICT` (a `STORE_BUSY` keeps its message and its `detail`: `lockPath`, and `holder` `{ pid, hostname, createdAt }` when the lock is readable), unrecognized failures become the method's fallback (`READ_UNAVAILABLE` for reads, `TRANSITION_REJECTED` for writes). `ROLLBACK_DETECTED`, `ANCHOR_LOG_UNREADABLE`, `WITNESS_UNREADABLE`, `INVALID_HISTORY`, `KEY_EXISTS`, `KEY_UNAVAILABLE`, `READ_UNAVAILABLE` and the other pass-through codes keep the engine's message and `detail`.
* **`AdministrativeProducerError`** never escapes the local API. The session-signed duty writes (`obligate`, `assign`, the attempt recorder) translate the producer's `phase:code`: `*:HEAD_MISMATCH` (the history moved, for instance while the signer ran) → `HISTORY_CONFLICT`; `SIGN:SIGNER_INVALID` / `SIGN:SIGNER_FAILED` → `SIGNER_FAILED`; any `CAPTURE:*` (including `CAPTURE:INPUT_LIMIT`) → `INVALID_INPUT`; every other `PREPARE:*` / `VERIFY:*` (no grant for the administrative action, a stale session, a rejected signed event, …) → `TRANSITION_REJECTED`. The message is `administrative transition refused (<phase>:<code>)` and `detail` is `{ producerError: "<phase>:<code>", phase, code }`. Engine-only codes you may see from the store and anchor functions: `HISTORY_EMPTY`, `STORE_BUSY`, `STORE_CONFLICT`, `WRITER_EXPIRED`, `RECEIPT_INVALID`, `ANCHOR_LOG_REJECTED` (an anchor target refused the attestation), `ANCHOR_LOG_UNREADABLE` (from an anchor log's `entries()` called directly, or from `openHistoryStore` for an unreadable `<path>.anchors`; `verify()` reports it as a failure instead), `REPIN_REFUSED` (`HistoryStore#repin`, §4), `WITNESS_INVALID_RESPONSE` and `WITNESS_REJECTED` (the remote witness client, §7a), `UNSUPPORTED_VERSION`, and the `ReplayCode` values (`INVALID_INPUT UNSUPPORTED_VERSION UNSUPPORTED_EVENT_SCHEMA UNSUPPORTED_EVENT_TYPE GENESIS_REQUIRED GENESIS_DUPLICATE EVENT_ID_DUPLICATE EVENT_TIME_REGRESSION EVENT_DATA_INVALID TRANSITION_INVALID CONTROL_AUTHORIZATION_INVALID`).

Decisions are not errors: `DENY` and `INDETERMINATE` are results.

* A consequential DENY in format 1 scans the history once for the session, tenure and intent events its binding names (§5).
* Opening a history (`openLocalOwner`, `openHistoryStore`, every runtime handle) checks that the file contains its pin, the pin's owner attestation and `<history>.anchors` (§4, §11); it does not read anchor logs kept elsewhere, flag forged log entries or a missing log the history recorded anchors in, which only `verify()` / `verifyHistory` do. Call `verifyHistory` after a restore and on a schedule, and decide on `ok` (`docs/SECURITY.md` §2). Remote witnesses are asked by owner-keyed writers before their first write, by `requireOnOpen` readers, and by `verifyHistoryWithWitnesses` / `irontrellis verify`; a plain reader without `requireOnOpen` does not ask the network (§7a).
* The store API is synchronous: a raw `store.append` cannot wait for the network. Owner-keyed raw appends queue their head statements (never signed before a verified witness answer) and `await store.flush()` submits them; the async owner API does the network checks itself.
* `ContinuityError` and `ContinuityErrorCode` are removed in the release after 1.0.

## Replay worker and cache contract

For a format-1 file of `SPECULATIVE_REPLAY_MIN_RECORDS` (1,024) records or more, the Ed25519 verifications run on worker threads while the replay proceeds, and the result is kept only if every one of them verified (otherwise the file is replayed again on the calling thread, which reports the exact first defect); `IRONTRELLIS_VERIFY_THREADS=<n>` sets the pool (default `min(4, cores − 1)`, 0 turns it off). A replay with caller-supplied `hooks` always runs on the calling thread. `verify()` on an open handle skips re-parsing a file whose length and SHA-256 equal those of the bytes the handle replayed. After that, no write path takes an event snapshot or replays the history: control writes, the execution path (`run`, `recordReceipt`, `collect`) and the session-signed duty writes (`obligate`, `assign`, the attempt recorder) work on the store's cached state.
